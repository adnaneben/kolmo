# Elastic thread budget and longest-first dispatch (review40 #7)

Branch `claude/elastic-dispatch` against `main` 896dc6d6. Execution only: every frame and every decoded file below has
the same SHA-256 on both binaries (column "same SHA-256").

## Method

- Machine: Apple M5 (4 performance + 6 efficiency cores, 10 threads), macOS, shared with other sessions' runs.
  **The load average was 10-170 during the night**, so wall times carry that noise. Every configuration ran main and
  the branch back to back, each under `tools/timed.sh` and a gate that waits up to a minute for the load to fall below
  10; the load at the start of each run is in the last column. Compare the pairs, not rows with each other.
- Inputs: `silesia.tar` (211,947,520 B), `enwik8` (100,000,000 B), and `mix2g.tar` (2,246,307,840 B: a tar of the
  review corpora, rival source trees, silesia.tar and enwik8).
- Commands: compress `kolmo --level L -T T -f -o OUT FILE`; decompress `kolmo -d -T T -f -o OUT FRAME` (the frame made by
  main at that level). Both binaries take the in-memory CLI path at levels 4-9 (the file path for those levels is the
  other PR), so the memory columns compare like with like.
- Measured by `measure.py` (review work directory `review40b/work/exec-R06R07/`): wall time, user + system CPU, peak
  RSS and peak memory footprint from `/usr/bin/time -l`, and the average RSS sampled every 20 ms.

## What to expect

- `-T 1` takes the old paths (no budget: one thread has nothing to lend), so it should match main.
- The gain is at levels whose blocks run a threaded match finder: level 9 (KLZMA on binary blocks) and levels 5-7
  (KLZH2 7-9), when a long block is still running after the other blocks are done. Level 8 codes every block with
  block sorting and level 4 with KLZH2 5 (no threaded finder): only longest-first dispatch applies there.
- Extra CPU: a block whose finder is split (any `-T` of 3 or more) pays for the split even when no helper joins
  (each chunk is walked once per class set and its matches go through an arena).

## #38 (crew spinning), measured, not changed

(main) 0.50-0.61 s, 2000/400 0.59-0.61 s, 200/50 0.57-0.58 s; `-T 2` 0.52-0.54 s for all three; same bytes. On this
machine the extra CPU at `-T 2`/`-T 4` over `-T 1` (0.35-0.39 s) is not spinning, so the constants stay.

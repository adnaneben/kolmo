# Kolmo concurrency and parallel planning implementation

The first implementation removes shared compression and planning state, hardens the container driver, and parallelizes planning for independent archive members. The independent codec and GPU research remain later milestones. The original assessment and measurements in the parent directory describe revision `31ce410`; they remain the baseline.

## Changes

- Format predictor flags belong to each compression job. Table encoders return their flags explicitly, and discarded analysis probes cannot overwrite another job's format version.
- Formula discovery receives its thread budget explicitly. Scientific record scoring receives its compression level through its search context. Neither uses a mutable process-wide setting.
- Independent archive members are planned in the existing worker pool. A single member can use parallel formula search; multiple members use one discovery thread per member, avoiding nested multiplication of thread counts. Plans and blocks retain input order.
- Codec contexts and scratch are reclaimed when temporary caller or helper threads exit. The pthread cleanup owns heap storage independently of platform thread-local destruction order. If destructor registration fails, the call releases its state immediately.
- The private worker fallback joins only successfully created helpers. Formula discovery processes remaining ranges synchronously when helper creation fails. Persistent helper creation also checks pthread attribute errors.
- Container and index arrays check multiplication, allocation and growth failures and preserve old pointers until replacement succeeds. Decode checks cumulative payload and output bounds. Buffers shorter than the minimum header and index fail before writing, and oversized range lengths are clamped without overflow.
- `czn_decompress_limited` adds optional output-size, raw-block-size and block-count limits. Existing APIs and the stream format remain compatible. These limits do not guarantee a bound on total codec heap memory.
- The development benchmark returns failure when an input/output fails, verification fails, or no settings are measured.
- Compression and decompression share one libbsc initialization guard. Python and Rust bundled sources contain the same changes. The shared-library Makefile target now rebuilds when included core files change.

## Measured performance

Fast-mode compression, in memory, median of five runs in randomized order on the same M5. Every measured frame was byte-identical across versions and worker counts and decoded correctly. MB/s uses original bytes divided by compression API elapsed time.

| Input | Threads | Before MB/s | After MB/s | Speedup |
|---|---:|---:|---:|---:|
| silesia/mozilla | 1 | 207.2 | 206.9 | 1.00x |
| silesia/mozilla | 4 | 271.3 | 665.9 | 2.45x |
| silesia/mozilla | 10 | 284.9 | 982.7 | 3.45x |
| silesia/nci | 1 | 164.5 | 164.1 | 1.00x |
| silesia/nci | 4 | 472.8 | 474.4 | 1.00x |
| silesia/nci | 10 | 666.5 | 669.8 | 1.01x |
| owid-co2-data.csv | 1 | 347.4 | 340.4 | 0.98x |
| owid-co2-data.csv | 4 | 1070.3 | 1065.1 | 1.00x |
| owid-co2-data.csv | 10 | 1279.7 | 1271.7 | 0.99x |

Mozilla benefits from independent archive-member planning: its ten-thread compression improves about 3.45 times without changing a byte of the frame. NCI and OWID changes range from about a 2 percent reduction to a 1 percent increase in this run. No confidence interval or cross-machine speedup is claimed from these five repetitions.

The portable phase timings isolate the cause: the earlier Mozilla planner took about 169 ms with ten threads while compression took about 19 ms. The updated planner distributes those member analyses across the pool, reducing median planning elapsed time to about 32 ms at ten threads. Member CPU-time sums and planning elapsed time are different quantities when work overlaps. Raw phase timings are in `planning-before.csv` and `planning.csv`; the full API comparison is in `performance.csv`.

## Verification

The focused resource test injects twelve container allocation failures, both decoder-index allocation failures, complete and partial helper creation failures, and failed thread-destructor registration. It checks formula discovery against its serial result when helpers cannot be created, valid-checksum malformed indexes, decoder limits, tiny buffers and an overflowing range length. Golden frames exercise versions 1 through 5: versions 1–3 follow the store-frame specification and were verified against the original library; versions 4–5 were generated by that library using linear and cubic grouped tables.

The concurrency test compares complete frames against serial references over 144 simultaneous table, archive and plain compression/decode operations, using different internal worker counts. A Python test adds 80 concurrent calls mixing two dictionaries and ordinary compression, including rejection of the wrong dictionary.

The pre-change library was preserved locally in `build/baseline`. Thirty-nine rt, fast and hc frame pairs across all twelve Silesia files and OWID retained identical payloads and decoded reciprocally. Ninety randomized fast-mode comparison runs require identical complete frames across old/new versions and 1, 4 and 10 threads, and verify every decompressed result.

Focused resource and concurrency tests passed under AddressSanitizer and UBSan, and the concurrency test passed under ThreadSanitizer on this M5. Vendored codecs were linked from the ordinary build, so sanitizer coverage applies to the core and test harnesses. The full native suite, language bindings and timing evidence are recorded beside this file.

## Reproduction

```sh
make -j10 all lib build/kolmo-profile
make check
make check-sanitizers
KOLMO_LIB="$PWD/build/libkolmo.dylib" python3 tests/test_concurrent_dict.py
CARGO_HOME=/tmp/kolmo-cargo-audit CARGO_TARGET_DIR="$PWD/build/rust-audit" cargo test --offline --manifest-path bindings/rust/Cargo.toml
python3 benchmark/audit/profile_planning.py
KOLMO_LIB="$PWD/build/libkolmo.dylib" python3 benchmark/audit/compare_versions.py
```

`compare_versions.py` and `check_compatibility.py` require the saved baseline dylib; a fresh checkout can rebuild the pinned original revision separately. The original library's SHA-256 is in the parent manifest. The before/after timing run uses two separately loaded libraries in one process, randomized order with five repetitions per setting, identical mode and thread parameters, and median elapsed time. It includes the full compression API but excludes input loading, output allocation and verification. The portable timing build measures planning and block execution separately using a monotonic clock; sums of member CPU phase durations can exceed elapsed planning time when those members run concurrently.

## Remaining work

Allocation failures inside every transform and every vendored codec are not yet exhaustively handled or injected. This implements container and scheduling failure paths, not a complete memory-failure audit. Decoder limits do not cover total memory, dictionaries or streaming through a limited API. CPU affinity and container quotas, a process-wide worker budget for many simultaneous callers, unseen corpus families, an independent residual coder and GPU kernels remain open work. A speedup on Mozilla is a measured archive-planning improvement, not a general leaderboard claim.

## 2. What was built, and why this way

Files: `src/algo/klz.c` (+521 lines: `kza_*` the tANS coder, `kz2_*` chunking and cost estimates,
`kolmo_klzh2_compress/decompress`, a shared `kzh_parse`), `src/algo/klz.h` (format), `src/codecs/codec.h`, `codec.c`,
`native.c` (id 32, table, opt-in word `lz2`), `src/core/memneed.c` (row), `Makefile`, `tests/test_native.c`,
`tests/klzh2_frames.h`, `tests/klzh2_frames2.h`, `tests/klz_rc3_hashes.h`, `tests/test_native_modes.py`,
`fuzz/fuzz_native_lz.c`, `benchmark/rc3w2/native/natbench.c` (`k2h1..k2h9`), `benchmark/review40/klzh2/*`,
`SPEC.md`, `research/CODECS.md`, `research/TRACKER.md` (row C7), `docs/NATIVE-PLAN.md`, both bindings' source
copies (last commit). I planned `src/algo/klzh2.c` as its own file; the code went into `klz.c` instead because it
shares the parse, the bit reader and writer and the length tables with codec 29 (static functions), and the
repository builds `klz.c` as one unit in five places (Makefile, two bindings, natbench, fuzz).

Design (all original Kolmo code; the tANS construction follows J. Duda, "Asymmetric numeral systems: entropy coding
combining speed of Huffman coding with compression rate of arithmetic coding", arXiv:1311.2540, tabled variant; no
code from FSE, zstd or any other project; zstd, LZ4 and the vendored libraries appear only as rivals in natbench):

1. **One token per sequence** = offset code x min(literal length, 3); literal-length codes only from 3; match-length
   codes in two streams (after a repeat offset / after a new offset). Alone, with khuf chunks: -1.74% / -2.11%
   against codec 29 (levels 1 / 3, commit `f08302a5`).
2. **Chunks aligned to the input**: a stream may start a chunk wherever the input crosses a multiple of 64 KiB;
   neighbours are joined by an integer cost estimate (same choice on every host).
3. **tANS for the code streams** (2^5-2^11 states, bit-reversal spread, compact count header, 2 states / 1 bit stream
   under 256 symbols, 4 states / 2 bit streams above).
4. **Finer match-length codes** and **coded low four bits of new offsets** (per-block flag, on for aligned binary
   data).
5. **Small inputs**: predefined tANS tables for code chunks under 1024 symbols (fitted by `gen_pre.c`, part of the
   format), tANS over bytes for literal chunks under 4096.
6. **khuf blocks for long code chunks at levels 1-4** (mode 3 from 1024 symbols): khuf decodes two symbols per
   lookup. +0.08% / +0.12% size for a stream decode 12% faster on six files; a judgement call, see section 6.

Alternatives rejected, with numbers (details in the branch's RESULTS.md, sections 3, 4, 6): a joint three-way
symbol (larger on six of six files); tables per 32 KiB with khuf's table format; conditioning contexts on the
sequence codes (-4.7% on nci as a bound, 0.2-0.5% on text, decode cost: not for the fast tier); branch-free sequence
loops (slower: 904-933 MB/s branchy against 817-840 and 745-803); larger split penalties (0.35% of size for 2% of
decode time); khuf for all code chunks of 2048 symbols or more (+0.36% on five files, measured against the earlier two-state coder).

Work of this session on top of the earlier attempt's five commits (`f08302a5`..`853de09d`):
- `a154f538`: the encoder codes one candidate per chunk, chosen by estimate (it coded two or three and kept the
  smallest), and scales counts with a heap instead of one pass over all symbols per state moved. 4 KiB blocks, level
  1: compress 0.51x -> 0.67-0.78x of codec 29; bytes of the 13-file totals unchanged, 4 KiB total +69 bytes.
- `c0e30b02`: khuf blocks for long code chunks (format extension inside mode 3; earlier frames stay valid).
- `ee0c7ea3`: tANS decode loop with packed entries and register-held states (stream decode -2%).
- docs, tools, bindings sync.

## 6. Decisions for the owner (flagged)

1. **No default changes.** Codec 32 is written only under `KOLMO_NATIVE=lz2`. Making it the `balanced` coder is an
   owner decision after the M5 run; on sizes it now beats the library path end to end (-0.62%), on this host it is
   slower to compress (parse) and 0.72-0.98x of zstd to decode.
2. **`KZ2_HUF_BIAS`** (khuf code chunks at levels 1-4): kept at 64. tANS only is 0.08% / 0.12% smaller (13 files,
   levels 1 / 3) and 3% slower to decode on six files. Same decoder either way.
3. **Format freeze.** The frozen frames pin the format as of this branch. `KZ2_PRE_*` (predefined tables) and the
   meaning of mode 3 (predefined under 1024 symbols, khuf from 1024) are part of it. Nothing has been released with
   id 32, so the owner can still change the format before merging; after that, a change needs a new id.
4. **Ids.** 32 (KLZH2) and 31 (KLZS, section 11) are taken on this branch; 30 is left for the w4-entropy lane (SPEC notes this).

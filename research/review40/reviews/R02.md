### What the entropy layer is today (rc3)

| coder | where | own? | state |
|---|---|---|---|
| zstd HUF (codec 13) | default Huffman of graph leaves, inside 22 | third party | default |
| khuf v1 (codec 27) | opt-in leaf Huffman, streams of KLZH (29) | own | greedy 11-bit limit, 2-symbol table, LSB first; (recorded) +0.16% vs HUF |
| rANS codec 14 | leaves at eco/hc/max/-x only | own | 4 x 64-bit states, 2^16 totals, 64 KiB slot table rebuilt per chunk, LEB128 table, 32 state bytes per chunk |
| binary range coder | QLFC (codec 18) | libbsc port | 12-bit probabilities |
| binary arithmetic coder | CM (7, 17, 25, 26) | own | 32-bit interval, 12-bit probability clamped to [1, 4095] |
| binary range coder | KLZMA (24) | own | 11-bit probabilities |

Code observations on the two files of my lens:

- `rans.c`: the decoder `malloc`s and fills a 64 KiB slot table for every chunk (`memset(sym + c[k], k, f[k])`), the
  encoder allocates `4 * (chunk + 64)` bytes per call and normalises with a `log2` scan of all 256 symbols per unit
  moved; every chunk pays 32 bytes of final states plus a table of 1-3 bytes per symbol. This is why
  (recorded, `benchmark/w4/entropy/RESULTS.md`) zstd's FSE is 4.3% and 3.3% smaller than codec 14 on Kolmo's own small
  leaf chunks (145,777 vs 152,370 and 193,190 vs 199,754 bytes) while both are equal on 128 KiB Silesia chunks, and
  why rANS decodes at 0.4-0.6 GB/s there. `balanced` never tries rANS for that speed reason (`fastleaf` in
  `kg_serialize`).
- `khuf.c` (rc3): the length limit is clamp + Kraft repair (not optimal), tables cost 2 bytes per symbol (sparse) or
  a nibble per symbol, four streams whatever the block size. All of this is already redone on the w4-entropy lane
  (package-merge, coded tables, multi-symbol MSB-first decode, BMI2 assembly), which is **not merged** and has a
  compatibility problem, see 3.4.
- Every leaf coder in the tree is **order 0** (Huffman, rANS) or an LZ/BWT library. There is no fast coder with
  contexts between "order-0 bytes" and "LZMA / BWT / CM". That is the gap this review builds on.

## 3. Gaps, ranked by expected gain

1. **No context-modelling entropy coder at leaf speed** (2.3, 2.4). Image residuals at `balanced`/`hc`:
   -5% to -9% with plain order 1 (coded bytes), -13% to -16% bound with neighbour-energy contexts; 16-bit medical
   image: -13.6% bound. 8-bit images at `balanced` are a recorded weak spot (79% larger than JPEG XL e9,
   `benchmark/rc3/leaders/RESULTS.md`). The world leaders' fast lossless image paths (JPEG-LS, JPEG XL's modular mode
   at low effort, FLIF/CALIC descendants) all code residuals under local-activity contexts; Kolmo codes them order 0.
2. **Order-0 rANS that is slower and fatter than it needs to be** (section 1): 32 state bytes + LEB table per chunk,
   64 KiB table per chunk, 4 states. Recorded: 3-14% smaller than Huffman on Kolmo's leaf streams but a third of
   its speed, so `balanced` skips it; krans (recorded, `KRANS.md`) reaches HUF's decode speed with 32 states on AVX2.
3. **khuf v2 is stranded on a lane that breaks rc3 frames** (3.4), so the leaves' default Huffman is still zstd's
   (originality rule) and KLZH still codes with khuf v1.
4. CM probability precision: measured -0.18% (2.5). Small.
5. Not measured by me, left unclaimed for the owners of those coders: KLZMA decode at 0.73x liblzma (recorded,
   `benchmark/w4/lz/RESULTS.md`); QLFC's four-part split on the w4-entropy lane changes `ratio` bytes by default
   (+0.05% to +0.23% recorded) and needs its own flag when that lane lands.

## 4. Plan

### 4.1 `ctx-rans-leaf` (claim #11, execute, primary)

**Design.** One new static rANS kernel, written for Kolmo (`src/algo/krans.c`; the experimental krans on the unmerged
branch is Kolmo's own earlier research and is the reference for the arithmetic, nothing third-party): 32-bit state in
[2^15, 2^31), 16-bit renormalisation words, totals 2^12 (2^11 for chunks under 4 KiB), at most one word per symbol
both ways, reciprocal-multiply encoder, final states must return to 2^15 and the word stream be consumed exactly (free
integrity check). Leaf codec id **33** (`src/codecs/krans_leaf.c`), three context modes chosen per leaf by the
encoder from exact counts and exact table sizes:

- mode 0, order 0: states by position modulo S (S = 1, 2, 4, 8 or 32 from the chunk length, so a 1 KiB leaf pays
  4-8 state bytes, not 32), chunks of 64 or 128 KiB, compact table (alphabet as runs or bitmap, frequencies in a
  bit-packed exponent/mantissa form);
- mode 1, order 1: context = previous byte; the chunk is cut into S contiguous segments, one state each, so the S
  context chains are independent (ILP now, SIMD later); a context whose own table does not pay shares the chunk's
  order-0 table (decision from exact costs, as in the krans research);
- mode 2, lag contexts: header carries a phase period P (1-4: channels), up to four lags (pixel step, row stride,
  stride +- step) and a quantiser id; context = bin(sum of |signed byte| at the lags, within the segment, 0 outside)
  x optional bin(|previous byte of the same pixel|) x phase. `kg_serialize` passes the IMG8 node's geometry; any
  fixed-stride leaf can use it.

Decoder: scalar C first, S interleaved states, branchless renormalisation, every table validated (sum exactly 2^M,
alphabet canonical), all reads bounded. AVX2 (gather, 32 states) and NEON kernels are follow-ups under the same claim.

**Integration.** One more candidate in `kg_serialize` and `kg_sel_sub` (so plane sub-leaves get mode 0/1), kept only
when smaller; allowed as a sub-codec in `planes_leaf.c`; `memneed.c` row; opt-in switch (`KOLMO_NATIVE=rans` and a
CLI flag); container version bit as the other new leaf ids. **No default bytes change.** rc3 decoders reject id 33
cleanly (unknown leaf codec).

**Files.** `src/algo/krans.[ch]` (new), `src/codecs/krans_leaf.c` (new), `src/codecs/codec.[ch]`,
`src/codecs/planes_leaf.c`, `src/transforms/graph.c`, `src/kolmo.c`, `src/core/memneed.c`, `src/cli/cli.c`,
`tests/`, `SPEC.md`, `research/CODECS.md`.

**Expected gain and basis.** 8-bit image files at `balanced`: -5% to -9% from mode 1 alone (coded bytes with the
research coder, 2.3), up to the -13% to -16% bounds with mode 2 minus tables; `hc`: -2% to -7% (mode 1), bounds
-10% to -14%; small plane leaves: the 28 state bytes and the table overhead of codec 14 per chunk.
`max`/-x: no gain expected from mode 1 (BWT wins, measured); mode 2's bounds are 3-5% under `max`.

**Risks.** Format: a new id only, opt-in. Decode speed: recorded krans figures on a similar VM are 290-370 MB/s
scalar and 540-750 MB/s AVX2 for order 1 against 1.3-1.6 GB/s for HUF, so image decode at `balanced` slows on the
leaf stage; a default switch therefore needs a size gate (the existing rule asks rANS for 3%) and the owner's
decision. Memory: decode tables up to 256 contexts x 4096 slots (1 MiB at one byte per slot plus frequency arrays);
bounded and declared. Binary size: about 10-20 KB. Encoder time: two passes plus table costing per leaf.

**Success measure.** Coded sizes with the switch against rc3 on the 17 PNM images, the OWID NPY arrays and the
leaf dumps, every frame decoded and compared by SHA-256; rc3 frames still decode (determinism set unchanged with
the switch off); `make check` and ASan/UBSan tests with corrupt and truncated leaves; indicative decode/encode
timings through `measure.py`. A negative result (tables eating the gain on some class) is reported as such.

### 4.2 `img16-ctx-rans` (claim #17, execute)

**Design.** Block codec id **34** for blocks whose transform is T_IMG: the transformed stream's 12-byte header, skip
and tail bytes are stored, the N residual samples are coded sample-major with the 4.1 kernel: hi byte under the
half-octave bin of the four causal neighbours' magnitude sum, lo byte under (min(hi,7), coarse bin); rows grouped into
S independent bands (one state each). The decoder rebuilds the exact transformed stream, then the unchanged
`img16_decode` runs. `compress_worker` codes it beside the block codec when `pl.t == T_IMG` and keeps the smaller.
Opt-in switch; no default bytes change.

**Files.** `src/codecs/krans_img16.c` (new), `src/algo/krans.c`, `src/core/blocks.c`, `src/core/decode.c`,
`src/core/memneed.c`, `src/codecs/codec.[ch]`, `src/kolmo.c`, `tests/`, `SPEC.md`, `research/CODECS.md`.

**Expected gain and basis.** Bounds of 2.4: mr -13.6% at `balanced` (2,316,428 -> 2,002,088 before about 20-25 KB
of tables), -11.3% against `hc`; x-ray -2.7% before about 40 KB of tables (so about -1.5%). Silesia's `balanced`
total moves by the mr amount.

**Risks.** A sequential context chain per band: decode speed well under zstd's on these blocks (to be measured;
bands give 8-32 independent chains). Small gain on noise images (x-ray): the trial costs encode time for little.
New block codec id (rc3 rejects it cleanly).

**Success measure.** mr and x-ray sizes at `balanced` and `hc` with the switch, round trip by SHA-256, the same
timing and test protocol as 4.1.

### 4.3 `khuf-v2-compat` (claim #18, planned)

The w4-entropy lane changes khuf's block format in place and says so (`khuf.h` on the lane: "rc3 codec 27 and 29
frames written before it do not decode"). **This violates the compatibility rule** for frames written by rc3 with
`KOLMO_NATIVE=huf|lzh`. Plan: keep rc3's v1 kernel for ids 27 and 29, bring v2 in as a second kernel under leaf id
35 (and the lane's khuf-then-zstd leaf as 30), tests on frames written by the rc3 binary, then re-measure v2 against
zstd's HUF before proposing it as the default Huffman of the leaves (recorded on the lane: -0.07% size, 1.22x decode
geometric mean on Silesia, encoder 0.75-0.94x on large chunks). The lane's QLFC changes are not part of this claim.

### 4.4 `cm-ac-prob16` (claim #19, planned, low priority)

16-bit final probability and coder interval split behind a new model flag. Measured -0.18% (2.5); only worth doing
together with a wider stretch domain, which is a model change with its own tuning.

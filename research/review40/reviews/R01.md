### 2.3 Where KLZH3's bytes go, and where the gap to zstd -3 is

`klzh_stats` re-runs the w4 parse per 4 MiB block and reports each stream as coded by khuf, plus entropy bounds.
`zseq_stats` takes zstd's own sequences for the same blocks and costs them in KLZH's code layout (same length and
offset codes, same repeat-offset rule, order-0 entropy per 128 KiB of symbols, no table cost) - one cost model for
both parses.

Level 3, bytes:

| file | zstd -3 | KLZH3 | zstd parse under the model | KLZH parse under the model | parse gap | zstd actual vs model | KLZH actual vs model |
|---|---|---|---|---|---|---|---|
| nci | 2,846,755 | 2,971,425 | 2,911,096 | 2,929,509 | +0.63% | -2.21% | +1.43% |
| xml | 636,164 | 672,831 | 664,603 | 664,850 | +0.04% | -4.28% | +1.20% |
| samba | 4,982,897 | 5,146,499 | 5,089,271 | 5,092,870 | +0.07% | -2.09% | +1.05% |
| dickens | 3,681,733 | 3,691,715 | 3,676,071 | 3,623,365 | -1.43% | +0.15% | +1.89% |
| osdb | 3,511,122 | 3,533,585 | 3,517,371 | 3,516,767 | -0.02% | -0.18% | +0.48% |
| webster | 12,151,695 | 12,252,033 | 12,138,040 | 12,072,497 | -0.54% | +0.11% | +1.49% |

**Finding 1 (the main one).** At the zstd -3 point Kolmo's parse is already level with zstd's (-1.4% to +0.6%
under one cost model; sequence counts within 1.6%). **The whole size gap is the entropy stage**: KLZH lands
0.5-1.9% above the order-0 model (whole-bit Huffman on skewed code streams, tables), zstd lands 2.1-4.3% below it
on structured data because its tables follow the input every 128 KiB while KLZH's cover 128 KiB of *symbols*
(often the whole 4 MiB block). At level 1 the same holds plus a parse difference in both directions (KLZH1's
parse is 1.0-4.6% better on xml, samba, dickens, osdb, webster and 3.1% worse on nci).

Composition (KLZH3, share of output): dickens literals 6.8%, sequence codes 32.6%, raw extra bits 60.7%;
xml 16.7% / 37.2% / 46.0%; samba 38.1% / 27.8% / 34.0%. Raw offset bits dominate text (TRACKER C2 says the same
of zstd).

Design options costed with **real khuf output** (not bounds) by `klzh_stats` (`out/stats2-w4-l{1,3}.tsv`):
- *Token layout*: one symbol per sequence = offset code x min(literal length, 3); literal-length codes only for
  ll >= 3; match-length codes in two streams (after a repeat offset / after a new offset).
- *Input-aligned sub-blocks*: tables per 128 KiB of input (existing khuf block format), chosen per file against
  whole-stream tables.

For reference the order-0 bound of the token layout without tables (what a static ANS coder could approach) is

Negative results kept: (a) a three-way joint symbol (ll class x ml class x offset class with escapes) is *larger*
than three separate streams on each of the six files of 2.3 (e.g. webster 4,412,789 against 4,148,736 bytes of entropy);
(b) tables per 32 KiB of input with today's khuf table format cost more than they save on nci, dickens, osdb,
webster (nci +10% on the entropy stage): the split must be chosen per stream and tables must be cheap or reused;
(c) simple conditioning contexts on the sequence codes (previous offset class, ll class), as an entropy bound against
the order-0 bound: -4.7% of output on nci, -0.2% on dickens, -0.5% on webster (level 3); not planned for the fast
tier (decode cost, and little on text).

### 2.4 Small blocks (graph leaves, table columns, small files)

`natbench-w4 lz4,klz1,zstd1,klzh1,zstd3,klzh3 1 {4,32,256} 3 xml dickens osdb` (25,623,410 bytes):

| block | KLZ1 vs LZ4 | KLZH1 vs zstd -1 | KLZH3 vs zstd -3 | KLZH3 compress vs zstd -3 | KLZH3 decode |
|---|---|---|---|---|---|
| 4 KiB | +6.2% (19,409,445 / 18,283,717) | +6.4% (14,769,225 / 13,876,738) | +5.6% (14,500,724 / 13,735,843) | 0.21x | 0.61x |

**Finding 2.** On 4 KiB inputs the native coders are 5.6-6.4% larger and KLZH3 compresses at about a fifth of
zstd -3's speed. Causes, measured with `klzh_stats 1 4 ...`: Huffman tables and framing are 18.0% of KLZH1's output

And `kz_parse_dfast` zeroes its full tables on every call whatever the input size (level 3: 2^18 + 2^17 entries =
1.5 MiB per 4 KiB block; one `klz_time-w4 3 BLOCK 1 0 samba` run - a parse pass, a compress pass and a decode pass -
takes 0.63 s of user time at 4 KiB blocks against 0.21 s at 64 KiB blocks, `rus.py`). This regime matters to Kolmo more than to a general compressor: every graph leaf and table column of at
least 64 bytes goes through this coder.

### 2.5 Encoder time

`klz_time-w4` (best of 5, indicative): the parse is about 61-73% of KLZH compress time at 4 MiB blocks (the lane's
callgrind says 45% parse / 17% Huffman / 20% sequence loop on webster). **Negative result:** I expected the five
`malloc`s per block (12 bytes per possible sequence = 3n, plus n, 3n/4, 3n, n) to cost page faults; with the heap
kept (`mallopt` thresholds raised) the minor-fault count for samba level 3 falls only from 14,689 to 12,522 and
system time is 0.03 s either way (large allocations are cheap here). Page faults are not where the time goes; the passes
over the 12-byte sequence array and the table zeroing on small inputs are.

### 2.7 Other findings

- **Finding 5, memory model.** `blk_dec_need` declares KLZH decode as `base + 2 MiB` ("as the library codec each one
  replaces"), but `kolmo_klzh_decompress` allocates the whole literal stream plus three code bytes per sequence:
  measured 2.32 MiB per 4 MiB block on x-ray and 2.70 MiB on sao (level 3), worst case 1.75x the block (28 MiB for a
  16 MiB `eco`/`hc` block; the worst case is from the code: nl <= n and ns <= n/4). By the code the encoder allocates
  3n for the sequence array on every call, plus n, n, and up to 0.75n and 3n. The declared figure is the library's, not Kolmo's.
- **Finding 6, fuzzing.** `fuzz/fuzz_codecs.c` covers codecs 16-23, 25, 26; no libFuzzer target reaches the decoders
  of 24, 27, 28, 29 directly (they have corrupt-payload tests under ASan/UBSan in `tests/test_native.c`). I read both
  LZ decoders line by line and found no unchecked read or write; that is a review, not a fuzz run.
- **Finding 7, mid levels.** KLZH5 (hash chains, depth 8, lazy) is 2.80% smaller than zstd -3 at 0.21-0.22x its
  compress speed (2.1). I did not measure zstd -5..-9 tonight; that comparison is the first step of the planned claim.
- **Finding 8.** `KOLMO_NATIVE` changes the coder, not the plan: `plan/frontier.c`, `transforms/sci.c` and
  `graph_typed.c` still score with zstd directly, so native output is judged by a rival's sizes (known to the
  native lane; not claimed by me).
- **Finding 9.** At level 3, KLZH's sequence array, hash tables and five buffers are per call; the vendored zstd
  keeps a context per thread (`codec_ctx.zc`). There is no native counterpart in `codec_ctx`.

## 4. Improvement plan

### 4.1 `klzh-entropy-v2` (execute, primary) - KLZH entropy stage v2 under new codec id 32

**Design** (original; inputs are the same `kz_seq` arrays, so every parse level benefits):
1. *Token stream*: one byte per sequence, `offset code * 4 + min(ll, 3)` (offset codes 0-26: three repeat
   offsets, then 3 + floor(log2 offset), as today). Literal-length codes are written only for ll >= 3 (code - 3);
   match-length codes go to one of two streams by whether the offset was a repeat. Extra bits stay raw. Most
   sequences then cost two Huffman symbols instead of three, and "no literals, repeat offset" can cost one bit in
   all instead of three.
2. *Sub-blocks by input position*: the encoder cuts each stream where the input crosses a multiple of 128 KiB
   and decides per stream, from the histograms (code lengths x counts plus the table bytes), whether to start a new
   table, reuse the previous table, or keep one table for the block. Deterministic (integer costs only).
3. *Small inputs*: a predefined code table for the token, length and literal-length streams (no table in the
   frame) offered next to the transmitted one; one Huffman stream instead of four below 1 KiB of symbols.
4. *Decoder*: decodes sub-block by sub-block into fixed scratch (bounded memory, cache-resident), then runs the
   sequence loop; one symbol fewer per sequence for most sequences.
5. *Optional step, only if 1-3 leave more than 1% on text*: an original static ANS coder for the token stream
   (inspired by "Asymmetric numeral systems: entropy coding combining speed of Huffman coding with compression rate
   of arithmetic coding", Duda, arXiv:1311.2540; no code from FSE or any other project). Decode speed decides.

**Files:** new `src/algo/klzh2.c` and `klzh2.h` (functions `kolmo_klzh2_*`), a parse hook in `src/algo/klz.c`
(codec 29's code and bytes untouched), `Makefile` (`NATSRC`), `src/codecs/native.c`
(codec table, opt-in word, e.g. `KOLMO_NATIVE=lz2`), `codec.h`/`codec.c` (id 32), `core/memneed.c` row for 32,
`tests/test_native.c`, `SPEC.md`, `research/CODECS.md`.

**Expected gain and basis:** section 2.3, real khuf sizes: -1.87% (sequence codes) and -0.38% (literals) at level 3
over 9 Silesia files, -1.30% and -0.51% at level 1. Small inputs: 18.0% / 9.6% / 8.6% of a 4 KiB block's output is
tables and framing today (2.4); how much of it predefined tables recover is to be measured. Decode: expected no
slower (fewer symbols per sequence); encode: one more histogram pass per sub-block (the lane's callgrind puts the
Huffman stage at 17% of encode time).

**Risks:** format - a new id only, written only under the opt-in; rc3 frames and codec 29 unchanged (tests decode
frames written by the rc3 binary). Speed - the sub-block decision must not cost more than about 3% encode time.
Memory - lower than today on decode. Binary size - to be reported (size of `build/kolmo` before and after). The gain is smaller on text than on
structured data; if the token layout fails to reach -1% on Silesia in total I report it as measured and keep the
numbers.

**Success is measured by:** natbench, 4 MiB blocks, 1 and 4 threads, Silesia + enwik8_10m (and 4/32 KiB blocks):
(1) KLZH2 level 3 total size <= zstd -3 (today +1.73%), level 1 at least 2.5% under zstd -1; (2) decode >= codec 29's
decode in the same process (interleaved A/B); (3) compress >= 0.97x codec 29's; (4) every block round-trips;
corrupt and truncated payloads under ASan/UBSan; (5) end to end `-m balanced` with the opt-in, `cmp` on every file;
(6) default output unchanged (`benchmark/determinism/check.py`).

### 4.2 `klz-w4-compat` (execute) - land wave 4 without breaking rc3 frames

**Design:** take the lane's `klz.c`, `khuf.c` (decoder speedups only; same khuf frames), `word_avx2.c` as they
are; restore rc3's interleaved KLZ decoder as `kolmo_klz1_decompress` and keep it registered for id 28 (decode
only); register the four-stream format as id 31 (encode and decode) and point `codec_native_id` at 31 for the LZ4
role; KLZH keeps id 29. Add test vectors written by the rc3 binary for ids 28 and 29 (`tests/legacy_frames.h`
style), corrupt-input runs for both KLZ decoders, a libFuzzer entry for 28/29/31 (and 32) in `fuzz/fuzz_codecs.c`,
SPEC rows.

**Files:** `src/algo/klz.c`, `klz.h`, `khuf.c`, `src/codecs/native.c`, `codec.h`, `codec.c`, `core/memneed.c`
(row for 31), `tests/test_native.c`, `tests/test_native_modes.py`, `fuzz/fuzz_codecs.c`, `SPEC.md`,
`research/CODECS.md`, both bindings' source lists.

**Expected gain and basis:** the lane's own measurements, reproduced in 2.1 for size (KLZ1 -5.33% against LZ4 on 13
files, KLZH1 -1.12% against zstd -1 with compress from 0.54x to about 1.0x) - gains that today cannot be merged.

**Risks:** none to the default (opt-in). The id table must be agreed with the w4-entropy lane (30) and R02 (33).
Bindings carry copies of `src/` and must be synced.

**Success is measured by:** rc3-written frames of ids 28 and 29 decode byte-exact with the new build (CLI frames
from `KOLMO_NATIVE=lz build/kolmo -m speed|balanced` of the base binary, `cmp`); `make check-native`; natbench
re-run of 2.1; determinism check unchanged.

### 4.3 Planned (owned, not tonight)

- **`klz-fast-parse-speed`**: tables sized to the input; emit while parsing (no 12-byte sequence array for the
  fast levels); two-position pipelined probe; per-thread workspace in `codec_ctx`; clang/AArch64 check on the M5.
  Target KLZH1 >= 0.95x zstd -1, KLZH3 >= 0.95x zstd -3, 4 KiB inputs >= 0.9x. Risk: parse changes alter opt-in
  bytes (format unchanged); to be flagged in the ledger. Measure: interleaved A/B in one process, natbench.
- **`klzh-rowhash-mid`**: 16-way tag rows compared with one SSE2/NEON compare for levels 4-7, lazy parse on top;
  original implementation of the publicly described row-hash idea. Target: KLZH5's ratio at >= 2x its speed.
  Risk: binary size (to be measured), and a NEON twin is needed for the M5.
- **`klzh-parse-adapt`**: minimum match / key length / skip per block from a 1-2% sample, deterministic; optional

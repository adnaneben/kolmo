# X-01 — per-plane leaves against an E03-style costed native baseline

Analysis only: no new measurement. Everything is recomputed from committed raw records by `x01.py`; its output is
`x01.json`. All three cohorts are observed data (development for any future rule).

## Boundary

Every figure is a complete-planner Kolmo frame from the production-connected harness: same production planner, same
KG_INT predictor and GCD, same blocks, only the residual leaf replaced. Real inputs with INT blocks only.

- `exist+ent` = the original residual layout; per leaf, the smaller of the existing Huffman-only and rANS coders with
  stored fallback, all trials charged. This is **E03's `native_base` policy**, expressed on Kolmo frames instead of the
  E2C1 envelope. Absolute byte counts are therefore not comparable with E03's tables; only the policy matches.
- `planes+ent` = the same policy per residual byte plane: one stream per plane, each with its own Huffman/rANS/stored
  choice. Per-plane codec mixing like this needs separate leaves; R1 notes that a single existing leaf can only carry
  aligned chunks of one codec. So `planes+ent` bounds R2's aligned-HUF / aligned-rANS controls from above rather than
  equalling them.
- `exist|planes + prod3|prod19` = production's own leaf rule (zstd family) at levels 3 / 19.
- Decode = median sequential single-thread reconstruction of every block, from the harness's shuffled end-to-end
  loops. It is not R2's warm/cold-controlled decode-only protocol.

## Result

| cohort, mode | INT files | planes+ent vs exist+ent | exist+ent vs production | planes+ent vs production | planes+ent decode vs production |
|---|---|---|---|---|---|
| dev, fast | 12 | **−11.14%** | +17.22% | +4.16% | 1.62× |
| dev, hc | 8 | **−8.27%** | +24.03% | +13.77% | 1.53× |
| E02E, fast | 9 | **−18.52%** | +14.11% | −7.02% | 1.54× |
| E02E, hc | 17 (8 single-byte ECG) | **−1.71%** | +0.68% | −1.04% | 1.47× |
| E02F, fast | 16 | **−4.32%** | +4.54% | +0.03% | 1.74× |
| E02F, hc | 13 | **−4.70%** | +7.41% | +2.37% | 1.70× |

Families with multi-byte residuals, `planes+ent` vs `exist+ent`:
- **dev**: audio −12.0% (fast) / −6.0% (hc); fs metadata −10.4%; raster −13.3%; series −17.1%.
- **E02E**: GHCN −19.8%.
- **E02F**: EEG −10.2% / −11.8%; pageviews −22.5% / −23.0%; speech −2.6%.

## Findings

1. **Against entropy-only native coding, per-plane modelling helps in every multi-byte family measured** — including
   the dense EEG and speech signals, where it did nothing against production's zstd leaves (E02F). The "sparse high
   planes only" pattern in E02E/E02F is specific to the zstd (hybrid) profile.
2. **The native baseline is far from production.** `exist+ent` is +4.5% to +24% larger than production frames.
   `planes+ent` closes most of that gap and beats production on GHCN (E02E fast −7.0%). It does not reach production
   in aggregate elsewhere.
3. **Decode cost is the obstacle for the native profile.** Entropy-only per-plane decoding is 1.5–1.7× production's
   (mainly rANS planes). R2's decode-only timing protocol is needed before any speed judgement.
4. This agrees in direction with R1's offline diagnostic on E02D (aligned/singleton candidates −5.24% vs native best).
   The two are on different boundaries and are not pooled.

## Consequences for the register

- P-01/P-02 (per-plane leaves, hybrid profile): unchanged — provisional, narrow.
- P-07 (per-plane entropy-only, native profile): **upgraded** from "workload-specific" to the strongest measured lever
  for a zstd-free profile, subject to decode cost.
- R2 (aligned chunks in one existing leaf plus singleton rANS, costed, with decode-only timing) is the right next
  experiment. This analysis supplies its expected-size reference on these three cohorts.

# P2-E29: preregistered fresh audio speed test with the research fast-inverse decoder (frozen before any file is read)

**Why.** P2-E20 H1 (production decoder) failed narrowly on fresh ESC-50 audio: 25/40. P2-E28 (development, same
clips) showed that a decoder whose KG_INT inverse is P2-E2's identity-checked `fi_inverse` lifts the rate to 35/40.
This test asks whether that holds on **new** audio.

**Source.** `microsoft/MS-SNSD` @ `fe61c4ba0d9ac8dd7e23d719cc79f8947e1dc742`: noise and clean-speech WAVs. It is not
referenced anywhere in the repository before this commit.

**Selection (`prepare_e29.py`, paths only).**
- One file per key, where key = top directory + stem without trailing digits (one per noise type or speaker group).
- Keys ordered by hash.
- Files of 100,000–5,000,000 bytes.
- The first 40 kept.

**Pipelines (`run_e29.py`, identical to P2-E28).**
- Research frames written by `p2e13 enc`, each decoded twice: by the production CLI, and by `kolmo-fastinv` (`_fd`),
  generated by `gen_fastdec.py` from the pinned `src/`.
- Controls: production `kolmo fast` with both decoders.
- Rival: zstd-3.
- N1 harness unchanged; two runs; `confirm`.
- Gate: as P2-E28, with leak detection on.

**Decision (`analyze_e29.py`).**
- **Primary.** `tp_phuf_pg16_fd` fits zstd-3's complete-CLI cost on every pair and is smaller. **Pass** if the
  one-sided Clopper–Pearson lower bound at alpha = 0.05/2 (second sequential audio speed test) exceeds 0.5 in both
  runs. Fewer than 20 inputs means inconclusive.
- Everything else is reported only, including the same frames with the production decoder.

A pass supports this claim: with the decoder's inverse loop replaced by the fast one (same format), the type-first
audio frame usually beats zstd-3 within its speed cost. Shipping that decoder change still needs authorization of
the `src/` and `tests/` change.
